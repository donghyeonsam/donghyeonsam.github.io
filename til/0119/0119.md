## CLI 명령어

- `cd “ 파일명 “` : 파일로 위치 이동 (change directory)
- `cd ..` : 이전 파일로 위치 이동
- `cd ../” 파일명 “` : 해당 파일로 한번에 위치 이동
- `start “ 파일명 “` : 해당 파일 실행 (macOS는 `open “ 파일명 “`)
- `python “ 파일명 “`: 해당 위치에 존재하는 해당 파이썬 파일 실행
- `Ctrl + `` : 터미널 창 오픈
- `clear` : 터미널 창 클리어
- `touch “ 파일명 “` : 새로운 파일 생성 (ex_ / sample.txt , [sample.py](http://sample.py) ‘’’’)
- `mkdir “ 폴더명”` : 새로운 폴더 생성
- `rm “ 파일명 “` : 해당 파일 제거 (휴지통으로 이동X 바로 사라짐)
- `rm -r “ 폴더명 “` : 해당 폴더 제거 (휴지통으로 이동X 바로 사라짐)
- `pwd` : 현재 작업 중인 위치 절대 경로 출력
- `ls` : 현재 위치에 있는 파일, 폴더들 출력

## Git 명령어

- `git init` : 해당 파일이 나의 프로젝트다 라는 것을 git에게 인식 시켜주는 명령어 (반드시 파일 내에서 실행)
    - git 계정 연동 (아래 사진 참고)
    
    ![스크린샷 2026-01-21 오후 10.20.07.png](%E1%84%89%E1%85%B3%E1%84%8F%E1%85%B3%E1%84%85%E1%85%B5%E1%86%AB%E1%84%89%E1%85%A3%E1%86%BA_2026-01-21_%E1%84%8B%E1%85%A9%E1%84%92%E1%85%AE_10.20.07.png)
    
- `git status` : 현재 프로젝트에 git이 진행 상황을 얼마나 인지하고 있는지 확인 하는 명령어
- `git add “ 파일명 “` : Staging Area에 새로운 파일을 추가
- `git add --all` : 수정한 모두를 한번에 추가하겠다 (리스크 있음)
- `git commit -m “ commit file name “` :git에 새롭게 등록할 프로젝트 이름을 등록 (commit한다.)
- `git log` : commit 기록 확인 명령어
- `git push origin master` : git에 수정한 파일 업로드
- `git pull origin master` : 원격 저장소의 변경사항만을 받아옴 (업데이트)
- `git clone “ 원격 저장소의 주소 “` : 원격 저장소 전체를 복제 (다운로드)
    - 주의사항, clone 받은 프로젝트는 이미 git init이 되어 있으므로 이중으로 git을 등록 X
- `git log --oneline` : commit 된 파일의 로그를 볼 수 있음
- `touch .gitignore` : gitignore 파일 생성
    
    : 주의사항, git에 추가가 되어있는 파일은 추후에 gitignore에 등록하여도 제거 불가능함
    
                따라서, commit 하기전 gitignore 먼저 작성하는 것을 권장
    
    (gitignore.io : 쓰는 언어에 맞게 gitignore 파일 제작을 도와주는 사이트)
    
- `git rm —cached` : git 캐시 삭제
- `git revert <commit id>` : 특정 commit을 없었던 일로 만드는 작업
    
    (commit id → git log에서 확인 가능함)
    
- `git reset [옵션] <commit id`> : (옵션은 `--soft`, `--mixed`, `--hard` 세가지) 특정 commit으로 되감기

### 옵션 별 동작 방식

- - -soft
    - 삭제된 commit 들의 기록을 staging area에 남김
- - -mixed
    - 삭제된 commit 들의 기록을 working directory에 남김 (기본값)
- - -hard
    - 삭제된 commit 들의 기록을 남기지 않음

### Reset 주의사항

- Reset은 만들어진 commit을 되돌리는 행위
- Remote에 올라간 commit을 reset하게 되면?
    - Remote에 기록된 commit과 다른 commit 이력으로 작업하게 됨
    - 이미 Remote의 commit을 가지고 간 동료의 코드가 충돌을 일으킬 수 있음

→ Remote에 올라간 commit은 절대 reset 해서는 안됨

- 이미 올라간 commit의 경우 revert를 활용

## Git을 이용한 실습실 사용방법

1. `git clone URL`
2. `cd 파일 위치`
3. 실습 작업
4. `git add 파일`
5. `git commit -m 이름`
6. `git push origin master` 
    - 여기서 origin은 설정한 branch 이름
7. 제출 버튼 클릭

- 절대 경로 (Absolute Path)
    - 정문(루트, root, /) 부터 목적지 까지의 전체 주소
    - 누가 어디서 보든 항상 똑같은 주소
    - ex) /c/Users/ssafy/

- 상대 경로 (Relative Path)
    - ‘현재 내 위치’를 기준으로 한 주소
    - ‘저 방으로 가’ (Desktop/) 또는 ‘이전 방으로 가’ (..) 와 같음
